Radian628 Wikidot Usertools

Found a bug? Open an issue or a PR here!

Here's a few tools for making Wikidot (mainly the SCP Wiki) more bearable to use.

Usage

Nearly all of these usertools require a UserScript manager to properly use (though some can just be pasted into your developer console). Here are a few UserScript managers I recommend.

  • Violentmonkey
  • Greasemonkey
  • Tampermonkey

Usertools

Local Draft Backup

Installation Link

Create local backups of your Wikidot drafts while editing, so if Wikidot can't save your work, you won't lose your progress. Drafts are saved every 60 seconds, and are stored locally, on your machine, so you do not need an internet connection for this userscript to work.

Better Editor

Installation Link

Completely replaces Wikidot's editor with a CodeMirror-powered editor that displays side-by-side with the page you are editing.

Supports:

  • Syntax highlighting for [[module css]] and [[html]] (but not for Wikitext yet, unfortunately).
  • Resizeable layout.
  • Hit Ctrl-S at any moment to save without exiting the editor. The page on the right will automatically refresh.
  • Supports limited hot-reloading capabilities for CSS in CSS modules only. Will likely break if you add/remove a CSS module.
  • Run JavaScript at compile time to generate complex or repetitive instructions with relatively little code. All JavaScript is run in a cross-origin-isolated sandboxed iframe for security purposes. . JavaScript snippets are specified using WikiText or CSS comment syntax, with the string js immediately following the opening comment. So, for example, [!--js "Hello, world!" --] will add the string Hello, world! to your page's source.
  • This editor does not steal the edit lock. Thus, other users can make edits while you're editing. If your version is out-of-date by the time you save, you will see merge conflict markers, which you will need to resolve before the save will go through.

Custom CSS Widget

Installation Link

Adds a widget to the bottom right corner of every page, allowing you to quickly and easily inject extra CSS into it. This is primarily intended as a debugging tool for if you want to quickly add CSS to a page to see how it'll affect it in practice, and in a way you can easily copy over into a Wikidot CSS Module.

Also, if you highlight/select a CSS selector, all elements matching that selector will be given an outline, thus allowing you to more easily debug your CSS selectors.

Better Comments View

Installation Link

Changes comments in user:info profiles into infinitely-scrolling feeds, which can be filtered by wiki.

Unfuck All CSS

Installation Link

This userscript forcibly refreshes all CSS on every Wikidot page you visit, forcing the CSS to load properly. You likely don't need this userscript unless (1) Wikidot pages frequently look broken for you, and (2) clearing your cache does not fix the issue.

AutoHTTP

Installation Link

Usage Summary

This userscript is controlled by "directives" placed within a page's source (they can be placed within comments). Once one or more directives are in your page's source, a button will appear in the bottom left corner allowing you to activate the userscript.

  • Use !!!AUTOHTTP link filename!!! to load the resource at URL link to the Wikidot attachment with file name filename. The userscript will refetch all files on each page refresh, only reuploading them to Wikidot if their contents have actually changed.
  • (OPTIONAL) Use !!!AUTOHTTP_BUILDPOLL link!!! to repeatedly poll the HTTP resource at URL link. If this resource changes, the userscript will automatically refetch/reupload the files and then refresh the page, instead of you having to refresh it manually.

Manual

This userscript automatically fetches files from a local or remote HTTP(S) server and then (re)uploads them as Wikidot file attachments. It is intended to assist in creating automated build pipelines for Wikidot pages.

To identify which pages to (re)upload, the userscript analyzes the page source for "directives", which take the form !!!AUTOHTTP link filename!!!. Do NOT include any extra whitespace, as it will not work. Replace link with a full URL to the file hosted on the HTTP(S) server, and replace filename with the name you want the file to have when it is attached.

For example, you could use !!!AUTOHTTP http://localhost:8080/hello.png world.png!!! to take the file hosted at the URL http://localhost:8080/hello.png and upload it as the file attachment world.png.

Once you create one of these directives (surround it with [!-- and --] so it doesn't actually display on the page) and then save the page, a button should appear in the bottom left corner of the screen, allowing you to enable AutoHTTP. This manual step is here to prevent you from accidentally uploading files to other articles.

Upon every subsequent page reload, all resources will be re-fetched from your chosen HTTP(S) server(s), and will only be reuploaded to Wikidot if their contents do not match the last-uploaded version.

Hot Reload

Normally, in order for this script to register changes to files you've uploaded, you have to reload the page, at which point it will re-fetch and compare the files to the versions currently hosted on Wikidot. If you instead want it to automatically reupload the files and refresh the page whenever they've changed, you can use hot reloading.

To enable hot reloading, use the !!!AUTOHTTP_BUILDPOLL link!!! directive, where link is a URL that returns a string representing a "build version". If given, this directive instructs the userscript to repeatedly poll this endpoint. If, while polling this endpoint, it receives a response which is different from prior responses, it assumes that a new build has been released, meaning that some files have changed, meaning that it will re-fetch and re-upload them, before refreshing the page.

The reason why this endpoint is separate from the AUTOHTTP endpoint is because some uploaded files might be large and would thus be impractical to repeatedly poll.

Troubleshooting

Make sure the server you're using is CORS-enabled! And make sure you use the full URL (http:// or https:// included!)
